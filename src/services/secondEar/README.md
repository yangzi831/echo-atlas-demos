# SecondEar 蓝牙接入

`bluetooth.js` 和 `recorder-protocol.js` 复制自本项目的 `SecondEar_AI_Passport_Arduino/website/public/`（2026-09-13）。保留 UUID、ADPCM 解码、CRC 校验、补传和先暂存后确认逻辑。

接入修改：`receiveLive` 消费持续录音请求，防止恢复已有会话后再次自动启动。`input.ts` 在用户点击中选择设备，并将传输段在 IndexedDB 事务完成后交给协议确认。网页主流程从 `liveFrame` 接收 PCM，只对用户选中或本地检测到的事件建立独立声音记忆。

不要把模拟浏览器测试当作硬件验证。固件协议变化时应核对原始 Demo 和实机。

持续录音采用实时优先策略：新会话先注册接收监听、完成通知订阅，再发送 op 5 开始录音（SE05 固件会话号自增，并由元数据核对）；新会话无需 op 8。接入已有活动会话时初次订阅发送 op 8，此后发现帧序号缺口直接接收当前帧，不回退发送位置。缺口按样本数填充静音，并通过 `liveFrame(pcm, {gap:true})` 通知上层，持久化为 `audioGaps`，不能解释成真实环境静音。重复帧和 CRC 错误帧不当作有效声音。结束时丢失的尾帧按设备真实样本数补齐占位。

确认优先于元数据读取：约 250 ms 或 10 帧触发持久化，突发积压整批处理，只有保存成功后才发 op 7。保存期间新到帧不会被提前确认。只有恢复已停止的旧录音仍允许补传。固件缓冲固定为 250 × 320 / 8000 = 10 秒；页面长时间冻结、蓝牙严重阻塞或磁盘无法写入，仍可能触发设备保护停止。模拟测试覆盖丢帧、积压、并发到帧、尾帧长度与保存失败；不能替代实机测试。
