# 持续录音、转写、上下文理解与时间定位

更新日期：2026-09-13。本版按用户纠正后的理解重做主链路，取代此前以声学变化触发候选的实现。

## 当前链路

1. 第一步填写**想记住什么**，可由 GPT 整理为记忆约定，并保留不希望留下的内容。
2. SecondEar 蓝牙持续返回 8 kHz PCM。完整音频约每秒写入一次 IndexedDB；协议的累计确认等待存储完成，不以 GPT 或 ASR 成功作为收音前提。
3. 音频经本站 WebSocket `/api/echo-asr` 到服务端，复用原 Demo 的 Fun-ASR 协议连续转写。临时文本原位更新，确定句子才落盘并进入语义判断。
4. GPT 通过 ApiMux Responses API 对照约定，结合此前摘要与最近两分钟上下文判断。每批新确定句子约等待四秒聚合，模型请求串行；积压按最早未处理批次消化，不跳过旧句子。字符预算会缩短极密集的上下文，摘要承接更早前情。
5. 模型返回真实句子 ID 和原文证据范围；服务端拒绝虚构 ID、倒序范围及无效证据。客户端从完整原录音截取该范围，保存为待确认的记忆。重复范围被抑制。
6. 停止时先接收设备尾段、写完音频，再等待 ASR 最后一句与最后一轮语义判断。人可以试听、确认、撤回、补充理解。

声学特征现在只驱动画面，不再选择自动记忆。手动快门仍可留下最近十秒，但自动候选依据语义，长度由原文范围决定。

## 时间模型

- 会话记录 UTC `startedAt`、本地 IANA `timeZone`、采样率、累计样本数、接收状态和结束时间。
- **设备没有提供时钟**：起点为电脑收到首帧的时间减去该帧时长，`clockSource=host-first-frame-estimate`。它包含蓝牙传输延迟，不能声称是硬件精确采集时刻。遇到恢复的旧设备缓冲，原始墙钟时间也无法凭空还原。
- 句子的 `begin/end` 是 ASR 对原音频的毫秒位置；另存由会话起点推导的 `startedAt/endedAt`。ASR 边界本身有识别误差，采样定位不等于消除了该误差。
- 记忆保存 `startSample/endSample`（结束位置不包含在片段内）、会话 ID、起止实际日期时间、时区、原文、证据句子 ID。
- `aiJudgement.decidedAt` 是模型判断完成时间，单独保存，不替换录音发生时间。
- 音频提取检查数据是否连续。缺片或范围无效时显示错误，不拼接出假完整片段。
- 记忆与完整录音页面的原文可点击回听；定位到对应的音频位置。

## 完整档案与恢复

`echo-atlas-recordings` 数据库保存 sessions、chunks 和确定的 sentences。没有命中的内容仍有原始录音与文字；页面提供完整 WAV 下载。

转写故障不停止录音。结束后可选择“重新转写并按原约定分析”，按原顺序、约实时速度重放完整音频；只有转写成功才原子替换旧文字，然后按原约定重新判断。已有记忆范围不会被重复创建，人的撤回不会被恢复操作覆盖。

页面刷新或关闭会中断蓝牙与云连接；已写入数据仍在。未完成会话明确显示为中断或异常退出，不标为完整。历史版本的 `echo-atlas-bluetooth/segments` 缓存没有删除，也不与本版新档案混淆。

## 服务与数据流向

- ASR：阿里云百炼 `fun-asr-realtime`，音频经本站后端持续发送。8 kHz 扩展为 16 kHz，时长不变，不恢复高频音质。
- GPT：`https://apimux.top` 的 `gpt-5.6-sol`，接收约定、转写、前情摘要和已选范围；不直接接收音频。
- 浏览器不持有服务端密钥。`.env.local` 已被 Git 忽略；变量名称见 `.env.example`。
- ASR 文本可能有误，GPT 判断也可能不符合人的理解；保留原声证据、确认和撤回。
- 没有语音的环境声不会通过本链路自动获得语义记忆，但完整音频照常保存，支持手动快门。

## 本地运行

```sh
npm install
npm run dev -- --host 127.0.0.1
```

开发与 preview 均包含 AI HTTP 接口和 ASR WebSocket。静态 GitHub Pages 无法单独运行此后端；本次未部署远程网站。真实蓝牙请用桌面 Chrome，先断开原 Demo 对设备的连接。
